## 二、D1 站点方案：mdBook + GitHub Actions + Pages

### 形态对比（决策依据）

| 方案 | 优点 | 缺点 | 判断 |
|---|---|---|---|
| 纯 GitHub 渲染（现状） | 零成本 | 无导航/搜索，〔标记〕裸露，阅读体验差 | 只作草稿期形态 |
| **mdBook**（推荐） | Rust 单二进制；SUMMARY 即目录；内置搜索；`{{#include}}` 可拼间奏；print 模式天生适合出书 | 需装工具链；中文搜索分词一般（可换激光搜索后处理） | **推荐** |
| VitePress/Hugo | 主题多、速度快 | 对"书"结构无原生支持，需自写目录组件 | 过度工程 |

### 架构（动手时的步骤草案）

1. `book.toml`：`title = "末法时代的钢琴家"`、`language = "zh-CN"`、开 print 支持；
2. `src/SUMMARY.md` 自动生成：小脚本扫 `正文/**/[0-9]*.md`（序章/终章/README 特判）按编号排序生成——**章内小节（## 一、二…）不动，只收章级**；间奏 README 下挂 5 则占位；
3. Pages 形态二选一（**待作者裁决**）：
   - A. 本仓库 GitHub Pages 子路径 `sit-music.github.io/the-lost-pianist/`（推荐：与既有站点联动，改动小）；
   - B. 独立域名/仓库（干净 URL，但多维护一处）；
4. GitHub Actions：`push → mdbook build → 部署 Pages`，草稿期可设为手动触发（workflow_dispatch），全书定稿后改自动；
5. **〔示意〕/〔我·待真实素材〕/〔待核实〕的站点显示策略（待作者裁决）**：
   - 保守：原样保留（诚实，但站点像草稿）；
   - 折叠：CSS 处理为浅灰/折叠块（推荐——保留诚实标记又不刺眼）；
   - 分离：正式站只收"干净版"，带标记版留在 repo（双维护，不推荐）；
6. 图表：SVG 直接入章（`![]()`相对路径已可用），无需转换。

## 三、D3 PDF 方案（摘要）

- **首选**：mdBook 自带 print 页（全章单页 HTML）→ Chrome headless 打印 PDF——零额外工具链，中文排版够用；
- **备选**：Typst 重排（排版质量高，但需为全书另写排版源，成本高）——除非要正式出版物级版式，否则不做；
- 字体：思源宋体/Noto Serif SC 内嵌；目录页由 print 模式生成。
- 结论：**D3 不单独立项，作为 D1 的 print 收尾动作**。
